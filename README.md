# программа бинарного дерева поиска на C++

программа для работы с бинарным деревом поиска. в ней можно добавлять, удалять и искать элементы. после каждого добавления и удаления дерево сохраняется в html-файл (по умолчанию «output.html»), где его можно посмотреть в виде схемы.

## возможности

- добавление элемента в дерево
- удаление элемента из дерева
- поиск элемента
- визуализация дерева в браузере (схема строится с помощью Mermaid.js)
- работа с разными типами данных: «int» и «double» (классы сделаны шаблонными)
- копирование деревьев: конструктор копирования и оператор присваивания
- узлы хранятся в умных указателях «std::unique_ptr»
- параметры запуска и конфигурационный файл (Boost.Program_options)
- тесты на doctest

## структура проекта

```
tree/
├── include/
│   ├── tree.h         - классы Node и Tree
│   └── html.h         - функции f1 и f3 для html-файла
├── src/
│   ├── tree.cpp       - реализация классов Node и Tree
│   └── html.cpp       - реализация функций f1 и f3
├── tests/
│   └── test_tree.cpp  - тесты для дерева
├── main.cpp           - меню программы и разбор параметров
├── tree.cfg           - пример конфигурационного файла
├── CMakeLists.txt     - сборка через CMake
└── README.md
```

в папке «include» лежат заголовочные файлы с объявлениями, в папке «src» их реализации. весь код находится в пространствах имён «utils::tree» и «utils::html».

## как устроен код

**шаблонные классы.** «Node» и «Tree» не привязаны к одному типу данных, поэтому в дереве можно хранить и целые числа, и числа с запятой. в «main.cpp» используется дерево для целых чисел: «Tree<int>». чтобы шаблоны работали, в конце файла «tree.cpp» отдельно указано, для каких типов создавать код (int и double).

**умные указатели.** корень дерева и левый и правый потомки каждого узла хранятся в «std::unique_ptr». поэтому память освобождается сама и вручную удалять узлы не нужно. указатель на родителя обычный, потому что родитель узлом не владеет.

**копирование дерева.** в классе «Tree» есть:

- конструктор копирования «Tree(const Tree &other)»: создаёт новое дерево, в котором все узлы скопированы заново
- оператор присваивания «operator=»: делает то же самое для уже существующего дерева, а старое содержимое при этом удаляется

благодаря этому копия получается независимой: если изменить её, оригинал не поменяется.

## параметры запуска и конфиг

программа понимает такие параметры:

| параметр | что делает |
|---|---|
| «-o», «--output» | имя выходного html-файла (по умолчанию «output.html») |
| «-v», «--values» | элементы, которые сразу добавляются в дерево |
| «-h», «--help» | показать справку |

пример:

```
./build/search_tree -o result.html -v 5 3 8
```

те же параметры можно записать в файл «tree.cfg», который лежит в папке, откуда запускается программа. каждый элемент пишется отдельной строкой:

```
output=result.html
values=5
values=3
values=8
```

если параметр указан и в командной строке, и в конфиге, берётся значение из командной строки. если файла «tree.cfg» нет, программа работает с параметрами по умолчанию.

## сборка

для сборки нужен CMake. при первой настройке CMake сам скачивает библиотеку Boost, поэтому нужен интернет, и это может занять несколько минут.

```
cmake -S . -B build
cmake --build build
```

если на Windows используется MinGW, при настройке нужно добавить генератор:

```
cmake -S . -B build -G "MinGW Makefiles"
```

## запуск

```
./build/search_tree
```

на Windows: «.\build\search_tree.exe»

## как пользоваться

при запуске в консоли появляется меню:

```
1 - добавить элемент
2 - удалить элемент
3 - поиск элемента
4 - выход из программы
```

нужно ввести номер действия, а затем значение элемента. чтобы html-файл закрылся правильно, выходите из программы через пункт 4.

после завершения откройте html-файл в браузере, чтобы увидеть результат. схема рисуется скриптом Mermaid.js, который загружается из интернета, поэтому для просмотра нужно подключение к сети.

## тесты

тесты написаны с помощью библиотеки doctest. сам файл «doctest.h» в репозитории не хранится, его нужно скачать самостоятельно:

1. скачать «doctest.h» со страницы github.com/doctest/doctest (папка «doctest»)
2. положить файл в папку «tests»
3. заново настроить и собрать проект (команды из раздела «сборка»)

если файл «tests/doctest.h» на месте, CMake соберёт программу «tree_tests». запуск:

```
./build/tree_tests
```

на Windows: «.\build\tree_tests.exe». в конце doctest сообщит, что все тесты прошли.

тесты проверяют добавление и поиск, удаление (лист, узел с одним и с двумя потомками, корень, отсутствующий элемент), конструктор копирования, оператор присваивания и дерево из «double».
